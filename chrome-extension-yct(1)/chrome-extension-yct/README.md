# 一窗通填报助手（Chrome MV3 扩展）

在**你自己的、已经登录的 Chrome** 里，按企业档案识别并填写上海一窗通
（`online.yct.sh.gov.cn`）的申报表单。登录、实名、人脸、扫码、电子签名与最终提交的
决定权始终在你手里。

设计取舍见 [DESIGN.md](DESIGN.md)。

## 安装

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择本目录 `chrome-extension-yct/`。
3. 点扩展图标 →「档案与设置」→ 底部「打开自检页」，确认全绿。
4. 在同一页粘贴企业档案 JSON（可先点「载入示例」看结构），保存。

扩展只在 `https://online.yct.sh.gov.cn/*` 上生效，其它站点不注入、不动作。
装上后面板默认是**收起**的，页面右侧只留一个竖条，点一下才展开。

### 自检页

`src/ui/selftest.html`（也可以直接用 `file://` 打开）按 manifest 的顺序加载引擎的
每个模块，对合成的 Element Plus 结构跑断言，并逐个解析扩展的其余脚本：

- 13 个引擎模块是否全部注册（任何一个语法错都会让后面的静默不装载）
- 控件分类会不会认错 `el-select` / `el-autocomplete` / 只读 popover 触发器
- `上海` 能不能对上 `上海市`，两个候选时会不会停下来
- 承诺书弹窗会不会被自动点掉、密码框会不会进填写计划
- 打了接口嗅探补丁之后，站点的裸 `fetch(url)` 调用是否仍然正常

全绿只说明**引擎这一层能跑**。页面表单填得对不对，仍要在业务页上用「只识别」核对。

## 使用

0. 可信输入**默认已开**，不需要额外操作。点击类操作走 Chrome 调试通道派发**真实输入
   事件**（`isTrusted=true`），专治政务站自绘下拉「点了没反应」。运行时页面顶部会出现
   「正在调试此浏览器」提示条，属正常现象；点掉它即当场收回，插件会回退普通合成事件，
   并且在你点「重置本次运行」之前不会自动连回来。
   要关掉这条通道，在「档案与设置」里点「停用」；它是软开关（Chrome 不允许把
   `debugger` 做成用时再申请的可选权限，该权限只能随扩展安装一次性授予），
   停用会立刻松开所有调试附着并拒绝后续派发，但摘不掉权限本身——真要彻底收回，
   请在 `chrome://extensions` 里停用或删除本扩展。
1. 打开申报入口（扩展弹窗里有「打开申报入口」按钮），**先自己完成登录与实名授权**。
2. 页面右侧出现操作面板。按这个顺序用：

   | 按钮 | 做什么 |
   | --- | --- |
   | 只识别 | 盘点当前页控件、展开每个下拉读回站点真实选项、给出映射计划。不改任何值。 |
   | 按档案填写 | 按计划填写，每个字段写完立即回读两次核验。 |
   | 处理弹窗 | 纯提示类自动点掉；要填的弹窗按子表单填好后交你确认；法律/身份类一律停下。 |
   | 下一步 | 页面无校验错误、无未决弹窗时才点，并等待页面真正进入新步骤。 |
   | 复核并提交 | 需要**连点两次**：第一次只展示识别到的提交按钮供你核对。 |
   | 导出诊断 | 把字段清单、填写计划、每个下拉的弹层结构与留痕打包成 JSON 复制到剪贴板。排障时直接粘贴。 |
   | 重置本次运行 | 清空留痕与提交闸门，换一个申报重来时用。 |

3. 面板会把没填的控件按原因分组列出来（未映射、档案缺这条、选项里没有这个值、
   法律声明需你本人勾选……）。**没有静默跳过的字段**。

4. **档案不用手写全对。** 某个字段选不中时，面板会把站点实际给的合法值列成
   **可点的按钮**——点一下就写回档案并自动重填。分步向导（如组织形式）一次点一级，
   点错了用那一行的「清空这一项」重来。档案是这样逐步「点」出来的，下次同一申报
   一次就过。

## 排障：下拉选不中

面板对下拉失败分了四种，**四种的下一步完全不同**，先看清是哪一种：

| 面板显示 | 含义 | 你该做什么 |
| --- | --- | --- |
| 选项面板开了，但里面一个选项都没有 | 弹层开了，站点没给数据。面板会把弹层原文一起显示 | 第一怀疑对象是**未登录**——字典接口被拦会返回「请登录后再试」；其次是上游级联字段还没选 |
| 这是分步选择器，弹层里只剩「请先选…」的提示 | 弹层里只有 `1. 请选择企业类型` 这类静态提示，没有真选项 = **上一步还没做**。「组织形式」就是这种 | 在档案里补上它提示的那一项（面板会直接说要补哪个键，如 `enterprise.enterprise_type`），插件就能替你把两步都点掉；或者先在页面上手动选掉第一步 |
| 试了四种展开方式都没能打开选项面板 | 各种姿势（可信点击 / 内层冒泡 / trigger / wrapper / 键盘）全试过了 | 先看设置页是否已启用「可信输入」——合成事件对部分自绘组件天然时灵时不灵。已启用仍打不开的，控件多半被遮挡或被站点禁用：看看是不是有弹窗压在上面，或这个字段需要先满足别的条件才可编辑 |
| 选项里没有档案里的这个值 | **弹层开了、选项也读到了**，只是没有匹配的 | 面板会把**站点实际给的选项**列出来。把档案里的值改成其中一个，再点「按档案填写」。典型：档案写「有限公司」，站点是「有限责任公司」 |
| 匹配到多个选项，需要你指定 | 档案值同时像好几个选项 | 把档案值写得更完整，让它精确等于其中一个 |

插件在「精确 → 归一化 → 唯一前缀」三级都匹配不上时会停下来，**不会挑一个相近的替你选**。
「上海」能自动对上「上海市」（唯一前缀），但「有限公司」对不上「有限责任公司」——
两边互相都不是对方的前缀，这种必须你来定。

### 自动补全（行业表述这类）

「行业表述」有**两个不同的值**：打进输入框的**查询词**（站点按它搜候选，也是选完后
框里最终显示的内容），和下拉里**要选中的那一条**（括号里的主营行业代码才是真正绑定
的东西）。把整串打进输入框，站点一个候选都搜不到，还会判非法并清空。

插件的处理：**查询词自动从选中项推导**（取第一个括号之前的部分），依次试
「档案显式给的第一段 → 括号前那段 → 整串」，第一个搜出候选的赢。所以档案里
只写选中项整串就够了：

```json
{ "enterprise": { "name": {
    "industry_expression": "信息科技 (主营行业:通信、信息、数码科技(12678))" } } }
```

也可以显式写成两段 `["信息科技", "信息科技 (主营行业:…)"]`，两种都认。

| 情况 | 处理 |
| --- | --- |
| 候选里有要选的那条 | 点中它，回读按查询词那一侧比对 |
| 一个候选都没出来 | 这个控件本来就允许自由输入，保留括号前那段文本 |
| 有候选但选不中（歧义/没有） | **判失败**，站点候选做成**可点按钮**——点一下写回档案并自动重填 |
| 站点把值判非法清空了 | 单独报 `cleared_by_site`，并把用查询词搜到的候选列出来供点选 |

只写「信息科技」会同时命中多条只差行业代码的候选 → 判歧义停下来。选哪个行业代码
是业务决定，插件不替你挑——在面板上点你要的那条即可。

### 分步选择器（组织形式这类）

有些下拉点开之后是个**向导**。一窗通「组织形式」的弹层实测长这样：

```
1. 请选择企业类型
   内资企业 › 有限公司 / 股份公司 / 非公司企业法人 / 个人独资企业 /
             普通合伙企业 / 特殊普通合伙企业 / 有限合伙企业
   外资企业 › 有限公司 / 股份公司 / 有限合伙企业 / 特殊普通合伙企业 / 普通合伙企业
2. 请选择组织形式        ← 第一步选完才有内容
```

档案写成路径数组，逐级照抄弹层文案（两级同名是站点的真实写法，不是笔误）：

```json
{ "enterprise": { "name": {
    "organization_form": ["有限公司", "有限公司"] } } }
```

路径的容错规则（写多写少都能走通）：

- **同名重复项取第一个**（文档序第一个 = 内资那一支）。要外资那支，在最前面补分组名
  `["外资企业", "有限公司", ...]`——分组名优先于「取第一个」。
- 分组标题（「内资企业」）可写可不写：点得动就点，点不动当标题跳过。
- 路径比向导**浅**：停下来报「还差一级」，把下一级候选做成按钮，点一下自动补全路径。
- 路径比向导**深**：多出来的段忽略，不报失败（面板会提示建议清理）。

选错了想重来：点那一行的「清空这一项」，站点合法值会重新列出来供点选。

名称区划这类多级级联同样支持数组：`"administrative_division": ["上海市", "浦东新区"]`。

### 不确定弹层长什么样？点「探查弹层」

每个下拉那一行都有这个按钮。它会展开弹层，把容器类名、被识别成选项的、被识别成
提示的、以及整棵 DOM 轮廓原样倒出来。政务站点的自绘弹层猜不出来，看一眼最快。

## 排障：翻页没反应

多半是站点弹了一个**校验提示**。插件识别到「请修改 / 不符合 / 已存在 / 生僻字」这类
措辞时会把它整段端到面板上，并且**不会替你点掉**——点掉之后页面照样不前进，而那句话
本身就是原因。按它说的改完再继续。

## 企业档案

只存在本机的扩展存储里，不会被上传。路径写法两套都认：

- 平台运行面词汇（推荐）：`enterprise.name.trade_name`、`shareholders[0].name`、`personnel[0].role`
- 技能包词汇（回退）：`investors[0].name`、`people[0].mobile`、`enterprise.name.industry`

**不要**把密码、短信验证码、一次性口令、人脸凭证写进档案。插件识别到这类字段会直接跳过，
写进来只是徒增泄露面。

级联字段（如名称区划）可以给数组逐级选：

```json
{ "enterprise": { "name": { "administrative_division": ["上海市", "浦东新区"] } } }
```

## 平台接入（可选，不配也能用）

在「档案与设置」里填平台地址 + 一次性配对码即可配对（复用既有的
`/api/v1/chrome-extension/agent/*` 协议）。配上之后：

- 「同步字段别名」把平台 `form_schemas` 的别名拉下来**覆盖**内置表；
- 运行事件可回写平台审计。

**当前后端下发的是录制步骤而非企业档案**，所以接平台模式下档案仍然来自本地导入。
要让平台自动下发档案，后端需在 job payload 里带上 `case_data`。

## 这个插件不做的事

- 不读、不写、不记录密码、验证码、短信码、一次性口令。
- 不代做实名认证、人脸识别、扫码授权、银行卡核验、电子签名。
- 不勾选承诺书、声明、告知书一类的法律意思表示。
- 不在业务域白名单之外的页面上做任何动作。
- 不执行远程下发的 JavaScript。
- 最终提交只点一次；结果不明确时不重试，交给你本人查看页面。

「已提交」不等于「已核准」，也不等于「已领照」。

## 与仓库里另一个扩展的关系

`chrome-extension/`（Agent 工厂网页流程录制器）是**录制回放**式的：录一遍人工操作，
之后按定位器重放。本扩展是**结构化识别**式的：每次都重新盘点当前页、按语义映射档案、
逐条回读核验。两者面对同一类站点，但前者依赖页面结构稳定，后者依赖标签语义稳定。
一窗通是持续变动的 wujie 微前端，所以这里选了后者。
